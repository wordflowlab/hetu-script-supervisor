# 产品需求

## 背景与推导

筹备说明准备拍什么，场记还要保存实际拍了哪条、依据哪版剧本、画面起止发生了什么。故事日与拍摄顺序不同，服装、道具和动作状态可能在跨场重拍后失配。Agent可以理解和整理，工程负责固定条次、明确比较前提和保留旧记录。

生成成本和等待时间会变化，但固定作品、历史依据、具体意见与连续审阅仍需长期积累。固定工程避免让模型每轮重建结构；结构化数据与多种阅读方式共用同一专业成果。插件按需安装，让作者提出目标、Agent操作工程、作者在适合的工作面阅读和选择。

## 定义与首版

场记工作台是河图洛书JS／TS专业插件。让固定剧本、镜次条次、连续性观察和剪辑选择能够逐项回读、比较和接续。用户包括独立作者、编辑与外部Agent。默认旅程：读取固定剧本 → 故事日和镜次 → 固定条次与观察 → 明确比较关系 → 处理不一致或未知 → 固定剪辑选择 → 新稿复核 → 场记本与接续。

首版包含完整专业维护、准确来源回读、专业方案、固定意见、确定性检查和改稿影响、上下文、固定交接、JSON／Markdown／HTML工程及专业阅读本。功能必须经机器入口执行，作者可以自然语言提出目标，也保留人工优化入口。

## 边界

制作筹备拥有资源与计划，导演布景台拥有空间与机位，本包拥有条次及连续性记录；真实文件仍归宿主素材。没有实拍设备控制、自动识别穿帮、影片制作完成认证、外部发送或发布。正文、正式设定、素材、采纳与定稿由宿主和作者掌握，不另建数据库、模型渠道或内部Agent。

成功以真实创作、审阅、返工及下一轮接续为准，安装、动作数或文件存在都不足以代表完成。开发与验收状态只由08维护。
